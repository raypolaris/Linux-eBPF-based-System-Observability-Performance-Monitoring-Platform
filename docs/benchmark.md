# 性能数据

测试对象：块 IO 延迟采集器（kprobe + 内核态直方图聚合）。

目标是回答两个问题：

1. 开启采集后，会不会拖慢磁盘 IO？
2. 单次采集事件的开销有多大？

## 测试环境

| 项 | 值 |
|---|---|
| 内核 | 7.0.0-34-generic |
| 发行版 | Ubuntu 26.04 |
| 平台 | VMware Workstation 虚拟机，2 vCPU (Intel i7-14650HX) |
| 磁盘 | VMware Virtual S (SCSI, /dev/sda)，max_sectors_kb = 4096 |
| 根文件系统 | /dev/sda2，剩余空间约 690 MB |

## 测试方法

**负载**：反复重写同一个 100 MB 文件，4K 随机对齐直接写 + fdatasync，共 8 轮（累计写入 800 MB）。
反复重写同一个文件是为了避免占满磁盘（测试机根分区只剩约 690 MB）。

```bash
for r in $(seq 8); do
    dd if=/dev/zero of=$HOME/bench.bin bs=4k count=25600 oflag=direct conv=fdatasync
done
```

**采集器 CPU 时间**用 `/proc/<pid>/schedstat` 的第一个字段（sum_exec_runtime，**纳秒精度**）在负载前后取差值：

```bash
BPID=$(pgrep -x blkio)
S1=$(awk "{print $1}" /proc/$BPID/schedstat)
# ... 施加负载 ...
S2=$(awk "{print $1}" /proc/$BPID/schedstat)
```

为什么不用 `top` 的 %CPU：它的精度不足以测微秒量级的开销；schedstat 是纳秒级，能给出可信的数字。

## 结果

| 场景 | 负载耗时 | 采集器 CPU 时间 | 采集器 CPU 占用 | 采集到的块请求数 |
|---|---|---|---|---|
| 基线（不运行采集器） | 11.078 s | — | — | — |
| 运行 blkio 采集器 | 11.265 s | 0.0009 s | 0.008% | 2,522 |

推导：单次 kprobe 事件的开销上界 = 0.0009 s / 2522 ≈ **0.36 微秒**。

采集期间事件率约 **224 请求/秒**。

## 采集器输出示例（同一负载下）

```text
  latency(us)      count   distribution        (total: 688, max: 230)
    32 -> 63          5   |#                                       |
    64 -> 127        34   |#####                                   |
   128 -> 255       103   |#################                       |
   256 -> 511       201   |##################################      |
   512 -> 1023      230   |########################################|
  1024 -> 2047       93   |################                        |
  2048 -> 4095       17   |##                                      |
```

分布形状与 bpftrace 版本（kprobe:blk_mq_start_request + kprobe:blk_mq_complete_request）一致，
两者互为交叉验证。

## 结论

1. **对 IO 吞吐无可测量的影响**：开启采集后耗时 11.265 s，不开启 11.078 s，差 0.187 s（1.7%），
   与同一负载重复测量的抖动同量级，不能归因于采集器。
2. **CPU 开销可忽略**：0.0009 s / 11.265 s = **0.008%**（万分之零点八）。
3. **单次事件开销约 0.36 微秒**，主要花在两次 hash map 操作（记录起始时间、取出并删除）。

## 测量过程中踩过的坑（记录备查）

1. **不要写 /tmp**：测试机 /tmp 是 tmpfs（内存盘），往它写不会产生块 IO；而且内存压力触发的
   swap 会产生块请求，容易被误认为"dd 的 IO"，导致测出的对象根本不是想测的东西。
   必须写到真实磁盘路径（如 $HOME）。
2. **不要屏蔽 dd 的错误输出**：磁盘只剩 690 MB 时，多路并发写大文件会因 ENOSPC 静默失败，
   测出一组假数据。本文的数据是在用了 `>/dev/null` 之后又补测修正的。
3. **重定向时 stdout 是块缓冲**：采集器输出重定向到文件时，若进程被提前结束，缓冲区内容会丢失，
   看起来像"采集器没工作"。给采集器加 `setvbuf(stdout, NULL, _IOLBF, 0)` 可避免（见 TODO）。
